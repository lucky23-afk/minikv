miniKV

Go 1.24 • v1.0.0

A miniature Redis-like distributed key-value store featuring consistent hashing, master-replica replication, append-only WAL persistence, active TTL eviction, and a zero-dependency web dashboard.

GitHub Repository Benchmarks Quickstart

Architecture

miniKV separates request coordination from partitioned storage nodes. Clients interact with the coordinator via HTTP/JSON, which hashes keys onto a consistent virtual-node ring and routes requests to the authoritative primary node and its replicas.

Core Capabilities

Consistent Hashing
128 virtual nodes per physical host with binary search lookup. Rebalancing moves only ~1/N keys upon topology changes.
Storage & Eviction
Sharded hash table with 16 mutex stripes. O(1) LRU eviction tracking entry count and memory footprint.
Precision TTL
Lazy expiry on read plus an active min-heap background sweeper. Absolute timestamps survive node restarts.
WAL & Snapshots
Append-only log with per-record CRC32 validation, crash recovery handling torn tails, and atomic background snapshots.
Replication Engine
Sequential log streaming with auto catch-up via WAL or snapshot. Configurable synchronous ack wait or async propagation.
Failure Detection
Gossip-style heartbeats tracking node health through alive, suspect, and dead transitions with automatic failover.

Quickstart

Clone the repository and build binaries:

git clone https://github.com/kaushik/minikv.git
cd minikv
make build

Start a 3-node cluster and coordinator with Docker Compose:

docker compose up -d

Interact via HTTP API on http://localhost:8080:

# Store a value with a 60-second TTL
curl -s -X POST http://localhost:8080/api/v1/keys/user:42 \
  -H "Content-Type: application/json" \
  -d '{"value":"Alice","ttl_ms":60000}'

# Retrieve the key
curl -s http://localhost:8080/api/v1/keys/user:42

# Check cluster health
curl -s http://localhost:8080/api/v1/cluster/nodes
